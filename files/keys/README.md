# Публичные ssh-ключи

Сюда кладутся **только публичные** половины ключей (`*.pub`). Они не
секрет: по публичному ключу нельзя восстановить приватный, поэтому их
безопасно держать в репозитории открыто.

Приватным ключам здесь не место — они уехали бы в `/gnu/store`, который
читается любым пользователем машины.

## Один ключ на машину

Пара генерируется на каждой машине отдельно, приватная половина её
не покидает:

```sh
ssh-keygen -t ed25519 -C "dyens@$(hostname)"
cat ~/.ssh/id_ed25519.pub > files/keys/dyens-$(hostname).pub
```

Имя файла — `dyens-<hostname>.pub`, чтобы было видно, чей ключ откуда.
Компрометация одной машины не тянет за собой остальные, а отзыв — это
удаление одного файла и `reconfigure`.

## Подключить

`#:ssh-authorized-keys` принимает список:

```scheme
 #:ssh-authorized-keys `(("dyens" ,(local-file "../files/keys/dyens-vm.pub"))
                         ("dyens" ,(local-file "../files/keys/dyens-laptop.pub")))
```

## Порядок отключения пароля

1. Добавили ключ, `sudo -i guix system reconfigure ...`
2. **Проверили**, что вход по ключу работает: `./run-vm.sh ssh`
3. Только теперь `#:ssh-password-auth? #f` и ещё один reconfigure.

Выключив пароль до проверки, вы потеряете доступ по ssh, и останется
только консоль VM.

## Заодно про шифрование секретов

Эти же публичные ключи можно сделать получателями в `.sops.yaml`
(затем `sops updatekeys files/secrets/home.yaml`) — тогда машина
расшифровывает секреты своим
`~/.ssh/id_ed25519`, и переносить между машинами не нужно вообще ничего.
