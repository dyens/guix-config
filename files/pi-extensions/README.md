# Локальные расширения Pi

`home/pi.scm` устанавливает `comment.ts`, `notify.ts`, `pi-emacs.el` и расширение
`lsp-manual/` в `~/.pi/agent/extensions/`, а также GNU diffutils
и libnotify (команда `notify-send`). Emacs-модуль —
`files/emacs/lisp/dy-pi.el`, загружается из `files/emacs/init.el`.
Для Emacs-интеграции нужны `emacsclient`, Emacs и GNU diffutils.
`lsp-manual/` отдельно использует закреплённую зависимость `pi-lsp` 0.1.7.
Она не подключается как самостоятельное расширение: автоматическая диагностика
после `write`/`edit` отключена. `lsp_check({ paths: [...] })` вызывается по
необходимости для быстрой обратной связи, а не после каждой серии правок. Успешный
build/typecheck на тех же входах и конфигурации не дублируется без дополнительной
пользы от LSP. При проверке сначала заверши связанные правки, затем проверь нужные
сохранённые файлы одной серией. Навигация (`definition`, `references`, `hover`,
`symbols`) помогает исследовать код; поиск по тексту дополняет её для конфигов и
неиндексируемых связей. Недоступный сервер не считается успешной проверкой.
Подробности установки — [LSP в Pi](../../README.md#lsp-в-pi).

После `homerec` выполнить `/reload` в Pi. В уже открытом Emacs загрузить новый модуль:

```elisp
(load "~/vms/guix-config/files/emacs/lisp/dy-pi.el")
```

Без активации Guix Home:

```sh
pi --extension ~/vms/guix-config/files/pi-extensions/comment.ts
```

## Структурированные шаги с чистым контекстом

Отдельное opt-in расширение, default для `pi-ruclaw`/implement. `task_plan` сохраняет
checkpoint и шаги; `task_complete` — короткий итог/handoff и новый контекст.
Состоянием и generated plan.md владеет extension, не модель. Нет обязательных отчётов
на каждый шаг. Текущий шаг, нужные итоги и ограниченные проверенные чтения переносятся;
полный архив не попадает в prompt. Новые пользовательские указания сохраняются.
Prefix внутри шага не меняется. `/task_get_status` показывает
`Tasks: 10/300. Plan: path` без LLM. Старый `/plan-cycle` — для Markdown v2 recovery.
Lite остаётся отдельным экспериментом.

```sh
pi --extension ~/vms/guix-config/files/pi-extensions/plan-cycle/index.ts
```

`home/pi.scm` устанавливает runtime в `~/.config/pi-plan-cycle/`, не в глобальный
extension autoload. `pi-ruclaw` подключает его явно. Подробности, ограничения
compaction и пример запуска: [plan-cycle/README.md](plan-cycle/README.md).

## Объясни проще: `/wait-what`

```text
/wait-what
/wait-what Зачем нужен LSP?
```

Без аргументов объясняет предыдущий ответ; с аргументами — указанную тему или фрагмент.
Сначала даёт главный ответ одним предложением, затем структурированные детали:
короткие предложения, простые термины, активный залог, без вводного мусора.
Это запрос на объяснение, не разрешение продолжать реализацию или менять файлы.

Исходник — `files/pi-ruclaw/prompts/wait-what.md`. Guix Home устанавливает его как
`~/.pi/agent/prompts/wait-what.md` для обычного Pi; launcher `pi-ruclaw` подключает
тот же файл явно, не включая автозагрузку остальных templates. Новые Ponytail
runtimes также сохраняют шаблон. После `homerec` запусти `pi-ruclaw` заново;
в обычном Pi достаточно `/reload`.

## Вопросы пользователю: `ask_user_question`

Guix Home подключает `npm:@juicesharp/rpiv-ask-user-question@2.15.0` (MIT).
Модель сама вызывает инструмент со структурированными вопросами и вариантами;
дополнительного LLM-запроса для извлечения текста нет. Поддерживаются 1–4 вопроса,
одиночный/множественный выбор, свой ответ, заметки и previews вариантов. Рекомендация
не выбрана за пользователя. Esc отменяет; частичный ответ не решает пропущенные вопросы.

Это замена старого локального `answer/`: команды `/answer` и Ctrl+. больше нет.
Обычные ответы в чате по-прежнему допустимы. `grill-with-docs` и `to-spec` используют
инструмент при наличии UI; без него задают вопросы текстом. В RPC пакет использует
диалоги хоста с ограничениями; в headless инструмент не предлагается модели.

После `homerec` начни новую сессию Pi. Не обновляй зависимости посреди работающего
вопросника. Plan-cycle сохраняет исходные завершённые пары вызов/ответ вопросника
между шагами, включая отмены/ошибки как таковые; они не означают согласие. Не вводи
секреты в форму: ответы остаются в истории и контексте сессии.

[Upstream и клавиши](https://github.com/juicesharp/rpiv-mono/tree/main/packages/rpiv-ask-user-question).
Пакет зависит от `@juicesharp/rpiv-config`; дополнительная локализация интерфейса
через `@juicesharp/rpiv-i18n` необязательна и здесь не устанавливается.

Smoke установленной версии (без модели и реального TUI):

```sh
node --import ./files/pi-ruclaw/tests/peers.mjs files/pi-extensions/tests/rpiv-smoke.mjs
```

Для проверки отдельной временной установки задай `RPIV_PACKAGE_ROOT` — абсолютный
путь к каталогу пакета. Smoke проверяет native loader, headless, RPC выбор/отмену и
импорт TUI-графа; визуальные клавиши, tmux и узкую панель нужно проверить вручную.

## Desktop-уведомления

`notify.ts` вызывает `notify-send` один раз, когда интерактивный Pi окончательно
завершил работу (`agent_settled`). Промежуточные инструменты, повторные попытки,
автокомпакция и продолжения не создают уведомлений. Успех: «Pi — готово»,
неисправленная ошибка: «Pi — ошибка». При ручной отмене уведомления нет.

В теле только имя каталога проекта — без ответа, промпта или текста ошибки.
Имя экранируется для notification markup. Уведомление запрашивается на 5 секунд;
desktop daemon может использовать свои настройки времени показа.

Нужны X11/Wayland-сессия, D-Bus и работающий notification daemon, например dunst
или сервер уведомлений GNOME/KDE. libnotify сам по себе не запускает daemon.
В headless, JSON, print и RPC режимах расширение молчит. Ошибка `notify-send`
не прерывает Pi; предупреждение появляется один раз до восстановления работы.
Подпроцесс ограничен таймаутом в 3 секунды.

Проверка desktop отдельно от Pi:

```sh
notify-send --app-name=Pi 'Pi — тест' 'Проверка уведомлений'
```

После `homerec` выполнить `/reload`, затем отправить обычное сообщение в Pi.

## Выбор Emacs: `/emacs`

В каждом Emacs запустить свой именованный сервер:

```text
M-x pi-emacs-server-start RET work RET
```

В нужной сессии Pi:

```text
/emacs work
```

Кавычки тоже допустимы: `/emacs "work"`. Имена: 1–64 ASCII-буквы, цифры,
`_` или `-`. `/emacs` без аргументов показывает текущий выбор.
Команда Emacs не переименовывает уже запущенный сервер и не занимает чужое имя.
Если сервер уже запущен, используй его существующее значение `server-name`.

Привязка сохраняется в истории сессии Pi и восстанавливается при её загрузке.
Несколько Emacs могут иметь разные имена; несколько сессий Pi могут подключиться
к одному Emacs. При смене `/emacs` прежний доступный сервер отключается от этой сессии.
Если сервер отсутствует, Pi сообщает об ошибке: **не запускает ни новый Emacs,
ни daemon**, не приостанавливает свой терминал.

## `/comment`

1. Выполнить `/comment` после завершения ответа.
2. Последний текстовый ответ текущей ветки открывается в `*pi-comment*`
   выбранного Emacs. Если буфер уже содержит активный запрос или правки,
   создаётся `*pi-comment*<N>` — старый текст не затирается.
3. Править ответ, добавлять замечания в произвольной форме.
4. **`C-c C-c`** отправляет unified diff в исходную сессию Pi и запускает ответ.
   Отдельное подтверждение в Pi не требуется. **`C-c C-k`** отменяет запрос.

Emacs остаётся открытым. Сохранение файла не требуется: это обычный буфер,
не связанный с файлом. Исходный ответ в истории не меняется. Без изменений
ничего не отправляется. Thinking, картинки и результаты инструментов не включаются.

Правки привязаны к конкретному ответу, сессии и позиции в истории. Если агент занят,
отправку нужно повторить после его завершения. Если ветка/история изменилась или
выполнен новый `/comment`, старый запрос отклоняется; текст остаётся в Emacs.
После `/reload` или переподключения старые буферы могут иметь устаревший адресат:
создай новый `/comment` и перенеси туда правки.

## Отправка выделения или строк: `C-c p s`

В Emacs нажать **`C-c p s`** (`M-x pi-send-region-or-lines`):

- При активном выделении отправляется только выделенный текст.
- Без выделения — текущая строка целиком и пять следующих (до конца буфера).
- Отправка **сразу, без предпросмотра и подтверждения**. Проверь отсутствие секретов.
- Добавляются путь файла (или имя буфера), диапазон строк и отметка
  `[unsaved buffer]`, если файл изменён. Файл не сохраняется, текст не удаляется.

Нужно предварительное подключение `/emacs server-name`. При нескольких сессиях
Emacs предлагает выбрать адресата. Если Pi занят, дождись завершения и повтори
сочетание. Отправленный фрагмент запускает ответ Pi; изменения файлов требуют
отдельного запроса.

## `Pi:`-комментарии непосредственно в коде

```js
// Pi: Почему здесь нет проверки на null?
const name = user.name;
```

Поддерживаются реальные комментарии языка, например `// Pi:`, `# Pi:`,
`;; Pi:`. Маркер регистрозависимый; `Pi:` внутри строк не собирается.
В первой версии каждое замечание — текст после `Pi:` до конца строки.

В Emacs нажать **`C-c p c`** или выполнить `M-x pi-send-comments`:

1. Собираются замечания из **открытых файловых буферов текущего проекта**.
   Весь репозиторий не сканируется; удалённые TRAMP-буферы не включаются.
2. Если подключено несколько сессий Pi, выбирается адресат по рабочему каталогу
   и ID сессии. При одной подключённой сессии используется она.
3. В `*pi-comments*` появляется редактируемый предпросмотр: корень проекта,
   относительный путь, номер строки, текст замечания и **2 строки выше / 5 ниже**
   с номерами строк. Несохранённые буферы отмечены `[unsaved buffer]`.
4. Проверить адресата, текст и отсутствие секретов. **`C-c C-c`** отправляет,
   **`C-c C-k`** закрывает предпросмотр без отправки.

Файлы автоматически не сохраняются, комментарии не удаляются. Отправляется
снимок на момент создания предпросмотра, который может отличаться от диска.
Ассистенту предлагается отвечать по пунктам и при необходимости читать код,
но не менять файлы и не создавать коммиты без отдельного запроса. Это инструкция
модели, не техническое ограничение её инструментов.

## Локальный канал и ограничения

Обратная связь работает через Unix-сокет в приватном временном каталоге
с отдельным случайным токеном для каждого подключения. TCP/HTTP-портов нет.
Emacs и Pi должны работать на одной машине под одним пользователем.
Сокет и временные тексты удаляются при штатном завершении/перезагрузке расширения;
после аварии временный каталог может остаться. Закрытие Pi не уничтожает буферы Emacs.

Ответ, правки, замечания и diff ограничены 2 MiB. При ошибке отправки текст
сохраняется в Emacs. Если процесс оборвался после приёма сообщения, но до получения
подтверждения, перед повторной отправкой проверь историю Pi, чтобы избежать дубля.

## Проверки

```sh
node --import ./files/pi-ruclaw/tests/peers.mjs \
  --test files/pi-extensions/tests/*.test.ts
emacs --batch -l files/pi-extensions/tests/emacs.test.el \
  -f ert-run-tests-batch-and-exit
```

TypeScript-тесты включают настоящий локальный канал обратной связи и два
реальных именованных сервера Emacs. Создаются только отдельные тестовые серверы;
пользовательские экземпляры не закрываются. ERT проверяет синтаксис комментариев,
контекст, сохранение черновиков и клавиши отправки/отмены, включая Evil
(если он доступен). С `--batch -Q` тест Evil пропускается.
